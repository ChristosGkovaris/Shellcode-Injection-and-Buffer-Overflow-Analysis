
# Changelog

All notable changes to the Shellcode Injection and Buffer
Overflow — Memory Safety Analysis project are documented
in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- Conceptual system architecture diagram.
- Structured technical documentation for memory safety analysis.
- Documentation of stack organization and register behavior.
- Documentation of debugger-assisted vulnerability analysis.
- Experimental environment specifications.
- Functional and defensive validation methodologies.
- Documentation of software security mitigations.
- Responsible use guidelines.
- Technical references and academic documentation links.
- Development roadmap.
- Documentation of project limitations.

### Changed

- Restructured the README to improve technical clarity and readability.
- Corrected the repository description and technology classification.
- Clarified the distinction between the C-based application
  under investigation and the Perl research implementation.
- Reorganized documentation around memory safety and defensive
  software engineering.
- Standardized academic attribution and author information.

### Licensing

- Clarified the scope of the MIT License.
- Distinguished original contributions from academic starter code.
- Documented instructor-granted redistribution permission.
- Preserved original academic attribution and source-code comments.
- Clarified third-party copyright and licensing obligations.
- Documented outstanding third-party source-code provenance.

## [1.0.0] - Initial public version

### Added

- Experimental stack-based buffer overflow analysis.
- x86-64 Linux memory and register inspection.
- GDB-assisted vulnerability investigation.
- Perl-based experimental research implementation.
- TCP-based network application security analysis.
- Original academic project specification.
- Academic technical report.
- Project documentation and contribution guidelines.

### Known Limitations

- Original C-based laboratory application is not distributed separately.
- Reproducible experimental execution requires further verification.
- Compatibility with modern security configurations requires evaluation.
- Automated regression testing is not yet established.
- A hardened reference application is not currently distributed.
- Third-party source-code provenance requires further verification.
- Implementation is not intended for production deployment.
